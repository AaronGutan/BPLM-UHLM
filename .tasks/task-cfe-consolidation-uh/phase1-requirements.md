# Phase 1: Требования

## Исходный запрос
Спроектировать и реализовать расширение конфигурации для базы-приёмника УХ (`ICORU_DEV`, id реестра `uh-lm`), каталог `ICORUHM/uh-cfe-consolidation/`, под обмен консолидации с БП.

Полный архитектурный проект: [architecture.md](architecture.md).

## Ключевые требования

1. Целевая конфигурация: УХ 3.2 (`ICORUHM/`), база `ICORU_DEV` (сервер `DNA-DEVAPPS-1S0`, id `uh-lm`).
2. Создаётся расширение (CFE), не правка основной конфигурации.
3. Имя расширения: `КонсолидацияУХ`; префикс: `CncdUH_`; Purpose: `AddOn`.
4. План обмена: **`Консолидация`** (то же имя, что на БП), `DistributedInfoBase=false`.
5. Состав плана: пересечение состава BP-CFE с метаданными УХ; для всех объектов `AutoRecord=Deny`.
6. Роль приёмника:
   - только входящая загрузка БП→УХ;
   - 1 узел плана = 1 база БП (код = GUID «Этот узел» БП);
   - регистр `CncdUH_Источники` для привязки источника/организации/OData;
   - журнал `CncdUH_ЖурналОбмена`.
7. Транспорт/формат: классический обмен + PVD-правила. **Не использовать** `ОбменДаннымиБПУХ` (XDTO/EnterpriseData).
8. Сверка: инициируется из УХ через OData БП и HTTP `Consd_Reconciliation` на БП; на УХ HTTP — ping/health.
9. UI: подсистема `CncdUH_Консолидация`, обработки настройки/обмена/сверки.
10. Роли: `CncdUH_ОсновнаяРоль`, `CncdUH_АдминистраторОбмена`, `CncdUH_ОператорОбмена`.

## Ограничения
- Без Python (правило проекта); скрипты — PowerShell.
- Соблюдение стандартов 1С (`.cursor/rules/`, `.cursorrules`).
- Основная конфигурация УХ не изменяется без явного запроса.
- Базы клиент-сервер + MS SQL.

## Критерии приёмки (итог Phase 8)
- Расширение загружается в `ICORU_DEV` без ошибок.
- Настроен узел корреспондента на пару с `bp-copy`.
- Сообщение обмена, выгруженное из БП, загружается в УХ; объекты записываются.
- Сверка ОСВ/объектов показывает сопоставимый результат (или явный список расхождений).
- Документированы объекты, отсутствующие в УХ (`uh-missing-objects.json`).
