# Phase 0: Оценка сложности

## Задача
Создать расширение конфигурации (CFE) для УХ (`ICORUHM/uh-cfe-consolidation`) — приёмник обмена «Консолидация» из БП:

- симметричный план обмена `Консолидация` (имя как на БП);
- загрузка сообщений БП→УХ (PVD-правила, не XDTO);
- идентификация нескольких баз-источников БП;
- журнал обмена, настройка, сверка с БП (OData/HTTP);
- префикс собственных объектов `CncdUH_`.

## Оценка сложности: Высокая

Обоснование:
- Зеркалирование уже готового BP-CFE (`Consd_*`) с адаптацией под УХ 3.2.
- Большой состав заимствований (пересечение ~196 объектов БП с метаданными УХ).
- Риск отсутствия части документов БП в УХ — нужен явный manifest расхождений.
- Нужны: план обмена, регистры, общие модули, обработки, HTTP-сервис, роли, подсистема.
- Mapping организаций и постобработка загрузки — бизнес-логика на BSL.
- E2E-приёмка требует обеих баз (`bp-copy` + `ICORU_DEV`) и транспорта сообщений.

## Зависимости
- Готовое расширение источника: `acclmcopy-cfe-consolidation/`
- Артефакты БП: `.tasks/task-cfe-consolidation/`
- Исходники УХ для borrow: `ICORUHM/`
- Правила обмена: `BPLM-UHLM_light.xml` / связанные манифесты
