# Загрузка правил: два zip

Обмен односторонний **БП → УХ**. Конвертация общая, правила регистрации разные.

| Zip | Куда | RegistrationRules |
|-----|------|-------------------|
| `BPLM-UH33LM_remix.zip` | **БП (источник)** | полные |
| `BPLM-UH33LM_remix-UH.zip` | **УХ (приёмник)** | заглушка (пустой состав, нет ПРО) |

Не лить один и тот же zip на обе стороны. На УХ полный `RegistrationRules` ставит объекты в очередь на выгрузку.

## Почему на УХ remix в обоих слотах конвертации

При загрузке сообщения с БП платформа ищет ПКО в **правилах корреспондента** узла.
Если там пустая заглушка УХ→БП, ПКО нет → `Правила["Валюты"]` / «Поле объекта не обнаружено (...)».

Поэтому в обоих zip:

- `ExchangeRules.xml` — remix (БП→УХ)
- `CorrespondentExchangeRules.xml` — тоже remix
- `RegistrationRules.xml` — полные (БП) или `.tasks/RegistrationRules-UH-empty.xml` (УХ)

Пересборка: `.tasks/pack-rules-zips.ps1`.

## Шаги

1. Синхронизация **БП – УХ Консолидация** → **Загрузить комплект правил**.
2. На **БП** указать `BPLM-UH33LM_remix.zip`.
3. На **УХ** указать `BPLM-UH33LM_remix-UH.zip`.
4. На УХ снять уже зарегистрированные изменения узла, если очередь не пустая.
5. Удалить старое сообщение обмена и прогнать обмен.
