# План обмена Консолидация - Регистрация изменений

## Структура расширения

### 1. План обмена: `ПланОбмена.Консолидация`

**Файлы:**
- `ExchangePlans/Консолидация.xml` - метаданные плана обмена
- `ExchangePlans/Консолидация/Ext/Content.xml` - состав плана обмена (196 объектов)
- `ExchangePlans/Консолидация/Ext/ManagerModule.bsl` - модуль менеджера

**Модуль менеджера содержит:**

```bsl
// Регистрирует изменения для конкретного узла
ПланыОбмена.Консолидация.ЗарегистрироватьИзмененияОбъекта(Узел, Объект)

// Проверяет наличие движений по регистру Хозрасчетный
ПланыОбмена.Консолидация.ДокументИмеетДвиженияХозрасчетный(ДокументОбъект)

// Регистрирует изменения для всех узлов плана обмена
ПланыОбмена.Консолидация.ЗарегистрироватьИзмененияДляВсехУзлов(Объект)
```

### 2. Общий модуль: `Консолидация_РегистрацияИзменений`

**Файлы:**
- `CommonModules/Консолидация_РегистрацияИзменений.xml` - метаданные модуля
- `CommonModules/Консолидация_РегистрацияИзменений/Ext/Module.bsl` - код модуля

**Модуль содержит обработчики подписок:**

```bsl
// Обработчик подписки на событие ПриЗаписи документов
Консолидация_РегистрацияИзменений.ДокументПриЗаписи(Источник, Отказ)

// Обработчик подписки на событие ПриЗаписи справочников
Консолидация_РегистрацияИзменений.СправочникПриЗаписи(Источник, Отказ)
```

## Логика регистрации изменений

### Документы

При записи документа выполняется проверка:

1. **Пропуск при загрузке:** Если `ОбменДанными.Загрузка = Истина`, регистрация не выполняется
2. **Проверка проведения:** Регистрируются только проведенные документы
3. **Проверка движений:** Выполняется запрос к `РегистрБухгалтерии.Хозрасчетный` для проверки наличия движений
4. **Регистрация:**
   - Регистрируется сам документ
   - Автоматически регистрируются все справочники из реквизитов и табличных частей документа

### Справочники

При записи справочника выполняется проверка:

1. **Пропуск при загрузке:** Если `ОбменДанными.Загрузка = Истина`, регистрация не выполняется
2. **Проверка субконто:** Запрос к `ПланВидовХарактеристик.ВидыСубконтоХозрасчетные` определяет, является ли справочник субконто
3. **Регистрация:** Если справочник является субконто, он регистрируется для всех узлов

## Состав плана обмена (Content.xml)

### 196 объектов метаданных:

- **2 Chart objects:**
  - `ChartOfAccounts.Хозрасчетный`
  - `ChartOfCharacteristicTypes.ВидыСубконтоХозрасчетные`

- **117 Documents:**
  - Все документы с движениями по регистру Хозрасчетный
  - (кроме префикса "Удалить*")

- **77 Catalogs:**
  - Субконто из `ВидыСубконтоХозрасчетные`
  - Реквизиты документов с типом `CatalogRef.*`

**Все объекты имеют:** `AutoRecord=Allow`

## Следующие шаги

### 1. Создать подписки на события

Необходимо создать подписки на события для документов и справочников:

#### Подписка на документы:

```xml
<!-- Для каждого из 117 документов -->
<EventSubscription>
  <Name>Консолидация_ДокументПриЗаписи</Name>
  <Event>ПриЗаписи</Event>
  <Source>Документ.*</Source>
  <Handler>ОбщийМодуль.Консолидация_РегистрацияИзменений.ДокументПриЗаписи</Handler>
</EventSubscription>
```

#### Подписка на справочники:

```xml
<!-- Для каждого из 77 справочников -->
<EventSubscription>
  <Name>Консолидация_СправочникПриЗаписи</Name>
  <Event>ПриЗаписи</Event>
  <Source>Справочник.*</Source>
  <Handler>ОбщийМодуль.Консолидация_РегистрацияИзменений.СправочникПриЗаписи</Handler>
</EventSubscription>
```

### 2. Тестирование

После загрузки расширения:

1. Создать узел плана обмена "Консолидация"
2. Провести любой документ с движениями по Хозрасчетному
3. Проверить регистрацию изменений: `ПланыОбмена.Консолидация.ИзмененияДляУзла(Узел)`
4. Выгрузить изменения: `ЗаписатьИзмененияДляУзла(Узел)`

### 3. Альтернативный подход (без подписок)

Если не нужна автоматическая регистрация, можно:

1. Удалить общий модуль `Консолидация_РегистрацияИзменений`
2. Вызывать регистрацию вручную из кода обработок:

```bsl
ПланыОбмена.Консолидация.ЗарегистрироватьИзмененияДляВсехУзлов(Документ.Ссылка);
```

## Примечания

1. **Производительность:** Регистрация выполняется только для проведенных документов с реальными движениями
2. **Безопасность:** Проверка `ОбменДанными.Загрузка` предотвращает циклическую регистрацию при обмене
3. **Гибкость:** Модуль менеджера позволяет расширять логику регистрации без изменения подписок
4. **Отладка:** Все методы экспортные и могут быть вызваны из консоли запросов для тестирования
